### 1.3 Blockers

All four blockers sit at one seam: runner-api and run-notifier in the exec account against the WS-09 IAM, RBAC and CNP that let them run. Each blocker stops every run. All four were re-verified by hand against the files.

- **R1V-001** (NEW-A02-3; WS-09, WS-02): runner-api's IAM grants GetObject only on inputs/manifest.json, inbox/* and registry blobs/sha256/*, and ListBucket only on inbox/*; runner-service.md RS-4 reads registry `bundles/<release_bundle_id>.json` (pointer) at every admission, and RS-3/§2.2/§4 read agentrun_record, manifest.json and LIST the transcripts prefix for the evidence check and reconstruction. As written every createRun fails A-6 and the R1-047 evidence check cannot run.
- **R1V-002** (NEW-A09-1; WS-09, WS-02): runner-api's egress allowlist (DNS and toFQDNs) has no acme-replicant-<env>-ops bucket host, yet runner-api must GetObject kill-switches/v1/state.json (A-5, fails closed with 503 after 5 min) and PutObject exec-revocations/ (CCR-02-09); with default-deny egress every run admission fails closed and the revocation feed is never written.
- **R1V-003** (NEW-A09-2; WS-09, WS-02): Only agentrun-controller gets cluster-scoped namespaces get/list/watch; runner-api has only per-namespace RoleBindings (replicant-agentrun-writer), so it cannot read sbx-<t> Namespace labels that A-5/RS-5 require (WS-02 18:40Z XD-FIX-R1-031: 'controller and runner-api only read (namespaces get/list/watch)'), nor do the cluster-scoped AgentRun list/informer runner-service.md §4 uses. Every CreateRun admission fails.
- **R1V-004** (R1-214; WS-09, WS-02): Key policy, §1.1 roles, Python KmsKeyProvider and replicant-system key are in place, but the Go provider (and WS-02 runner-service.md payload-codec row) calls GenerateDataKey with a bare alias from the exec account (222222222222) while tenant keys live in the core account (111111111111); KMS resolves bare aliases only in the caller's account, so cross-account use needs the alias ARN or key ARN and every run-notifier Signal encode fails.
