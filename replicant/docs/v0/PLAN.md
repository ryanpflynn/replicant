# v0 build plan: local walking skeleton

Goal: get the bugfix flow running end to end on this laptop (macOS arm64, Podman 6.1, VM 6 CPU / 8 GiB, no Docker),
using production code paths and the frozen contracts.

**Naming (2026-10-25).** The product is **Replicant** (formerly "factory"; CCR-ORCH-02, INTERFACES-LOG RENAME-01). The
monorepo is `/Users/rflynn/replicant/replicant`, the CLI is `replicant`, images are `localhost/replicant/*`, the compose
project is `replicant`, and env vars are `REPLICANT_*`. Quick start: `uv run replicant dev up --profile v0`, then
`uv run replicant dev seed`.

Target, in the order the milestones prove it:

1. A Gitea issue labelled `replicant` triggers a job.
2. The job posts an ack comment.
3. The implementer, QA and reviewer runs execute in sandboxes.
4. The publish gate is approved through the API.
5. A PR is opened in Gitea and merged, and the job ends `succeeded`.

The spec is the source of truth: `/Users/rflynn/replicant/spec` (start at `spec/README.md`;
plan §1 is `spec/99-implementation-plan/plan.md`). Contracts are in `spec/00-contracts` (versions in `FROZEN.md`).
**Do not edit anything under `spec/`.** If the spec is wrong or ambiguous, record it in
`replicant/docs/v0/DEVIATIONS.md` (append only) and choose the option that is closest to the contract.

| M | Proves | Model backend | Git host |

Only M1 is in scope now.

## Repo and conventions

- **Layout.** The monorepo is `/Users/rflynn/replicant/replicant`, laid out as in `spec/11-local-dev/repo-layout.md` §1.
  Create only what v0 needs.
- **Python.** uv workspace with the root `pyproject.toml`, Python 3.12.
- **Go.** One `go.work` with Go **1.26**. The host Go is 1.20, so build and test Go inside containers
  (`docker.io/library/golang:1.26`) through Podman.
- **Containers.** Use `podman` and `podman-compose` (`/opt/homebrew/bin/podman-compose`). Use `podman build`, not buildx
  bake (a bake file is optional). Images are tagged `localhost/replicant/<name>:dev`.
- **Contracts.** Copy the machine-readable contract files verbatim from `spec/00-contracts` into `replicant/contracts/`.
- **Stack definition.** `spec/11-local-dev/compose/compose.yaml` and `config/` are the **authoritative map** of service
  names, ports, env var names, secret file names and dependencies. Copy them to `replicant/dev/compose/` and add a profile
  **`v0`** containing only the services listed below. Keep every name, port, env var and secret path exactly as
  specified, so the components agree without negotiating.
- **Secrets.** Local secret files are generated by `replicant dev up` into `replicant/dev/.secrets/` (gitignored). Nothing
  secret is printed.

### Sample repo

`dev/sample-repos/ledger-api`: a tiny Go service with one real bug and one failing unit test. The issue text describes
the bug. The gateway `script` backend's canned implementer response applies a known-good fix, so QA (`install`,
`unit`, `build`) passes, the reviewer response approves, and the risk is `low`. A low risk still opens the publish gate,
which is on locally.

## Definition of done for M1 (per component)

- It builds as an image, `podman build`, on this machine.
- Unit tests pass in a container or uv env.
- The component starts in the `v0` profile and reports healthy.
- A component-level smoke test against its real neighbours passes, or against contract fakes if the neighbour isn't
  ready yet. Say which.
- A short `README.md` in the component directory with run and test commands.

The orchestrator integrates and runs the E2E.
